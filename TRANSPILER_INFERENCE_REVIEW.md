# Transpiler Inference Review

## Constraint

The transpiler is **not present in this repo**. It resides in Oracle's internal Oracle-SDK monorepo and was used to generate the Swift files before this extraction. The comment `"Code generated by Go to Swift conversion; DO NOT EDIT"` appears in no public GitHub search results, indicating it is proprietary Oracle tooling.

This review infers transpiler behavior from:
- Generated file headers and structure
- `docs/WORKING_SWIFT_SDK_PLAN.md` (internal planning doc)
- Defect patterns discovered during the SDK parity review

## Observed Transpiler Behavior

### 1. File Mapping

- **Go service directory** (e.g. `oci-go-sdk/services/ailanguage/`) → **Swift service directory** (`ailanguage/`)
- **Go file**: `foo_bar.go` → **Swift file**: `foo_bar.swift` (kebab → snake_case, preserve rest)
- **Go package**: `package ailanguage` → **Swift target**: `Ailanguage` (PascalCase, added to `Package.swift`)

### 2. Type Mapping

| Go Type | Swift Type | Notes |
|---|---|---|
| `*string` (pointer) | `String?` | Optional, even if `mandatory:"true"` |
| `*int` | `Int?` | Optional |
| `*float64` | `Double?` | Optional |
| `bool` | `Bool?` | Optional (even for non-pointer bools in some files) |
| `[]T` (slice) | `[T]?` | Optional slice with defaulted init param |
| `map[string]string` | `[String: String]?` | Optional with default |
| `map[string]map[string]interface{}` | `[String: [String: Any]]?` | **Breaking**: `Any` not `Sendable` |
| `common.SDKTime` | `Date?` | Timestamp → Date |
| `Enum` (type string) | `typealias X = String` + `public enum X: String` | **Bug**: illegal redeclaration, 25/25 files in ailanguage |

### 3. Enum Handling

**Defect 1: Redundant `typealias` + `enum`**

Every enum file emitted:

```swift
public typealias FooEnum = String
public enum FooEnum: String, Codable, Sendable { ... }
```

This is a Swift redeclaration error. Verified with minimal `swiftc` repro:

```swift
public typealias FooEnum = String
public enum FooEnum: String, Codable, Sendable { case a = "A" }
// error: invalid redeclaration of 'FooEnum'
```

Working convention (from untouched `adm/operation_status.swift`):

```swift
public enum FooEnum: String, Codable, Sendable { ... }
public extension FooEnum {
    static var allValues: [...] { [...] }
    static func fromString(_ v: String) -> FooEnum? { .init(rawValue: v) }
}
```

**Defect 2: Duplicate enum companion files**

Some enums are split into `*_enum.swift` files (observed in `accessgovernancecp`, excluded via manual `Package.swift` target excludes). The plan doc notes this was "ideally in the generator rather than via manual excludes."

### 4. Interface / Protocol Mapping

**Defect 3: Go interface → Swift protocol + `any`**

Go:

```go
type InputLocation interface { ... }
```

Emitted Swift:

```swift
public protocol InputLocation { }
public struct inputlocation: Codable, Sendable { ... }
```

But fields typed as the interface name become `any InputLocation` (which is non-`Sendable`):

```swift
public var inputLocation: InputLocation?  // actually stored as `any InputLocation`
```

This blocks `Codable`/`Sendable` conformance. Working pattern from `adm/operation_status.swift` (no interface fields) suggests the transpiler should map to the concrete struct name instead.

### 5. Struct Properties

**Defect 4: `description` collision**

When a struct has a real `description` field (e.g. Go `Description *string`), the transpiler emits:

```swift
public var description: String??
extension MyStruct: CustomStringConvertible {
    public var description: String { ... }  // redeclaration
}
```

This breaks compilation. Plan doc notes this was "Rewrite `CustomStringConvertible` for models with a real `description` property."

**Defect 5: Bad optional interpolation in `description`**

Generated `description` interpolates non-String types directly:

```swift
return "Project(\n    timeCreated: \(timeCreated),  // Date? → String?
    definedTags: \(definedTags),                    // [String: [String: Any]]? → String
)"
```

Swift interprets optional types as `nil` strings in description, but `Date?` and collections produce non-String debug descriptions, causing type errors.

### 6. Go-only Types Not Mapped

**Defect 6: Unresolved imports**

Generated code references types that have no Swift equivalent:

- `byte` → should be `UInt8`
- `common.RequestMetadata` → should be in `OCICommon`
- `http.Response` → should be `URLResponse` or equivalent

These appear in request/response structs (`rawResponse: http.Response??`) and cause "cannot find type" errors.

### 7. Naming Conventions

- **Request files**: PascalCase `CodingKeys` (`case projectId = "ProjectId"`)
- **Model files**: camelCase `CodingKeys` (`case compartmentId = "compartmentId"`)
- **Headers**: `String??` (double optional) for optional header params (e.g., `opcRequestId: String??`)
- **Raw response**: `http.Response??` (double optional)

### 8. Embedded Body Structs

Go request bodies embedded with `` `contributesTo:"body"`` are **dropped** from the generated request struct. For example, `ChangeEndpointCompartmentRequest` in Go has `ChangeEndpointCompartmentDetails` embedded, but the Swift struct only has path/header fields — the body field is not present at all.

### 9. Module Splitting

Transpiler sometimes splits Go enum types into separate `*_enum.swift` files (observed in `accessgovernancecp`), producing more Swift files than Go source files. This explains why some folders have *more* Swift files than Go (e.g., `accessgovernancecp`: 27 Swift vs 22 Go).

## Inferred Generator Signature

Based on the observed patterns, the generator likely takes:

```go
// Input: oci-go-sdk services/ailanguage/*.go
// Output: ailanguage/*.swift
```

And applies these transformations per the eight conventions documented in `SDK_PARITY_REVIEW.md`:

1. `*T` → `T?` (universal optional)
2. Enums: emit only `public enum X: String`, no `typealias X = String`
3. Interfaces → concrete struct name
4. PascalCase CodingKeys in requests, camelCase in models
5. Header params → `String??`, raw response → `http.Response??`
6. `common.SDKTime` → `Date?`, tags → `[String: [String: Any]]?`
7. Drop embedded body structs from requests
8. Escape Swift reserved keywords in enum cases (`` case `class` ``)

## Recommended Generator Fixes

### Immediate (unblocks ailanguage build)

1. **Fix enum redeclaration**: Emit only `public enum X: String, Codable, Sendable` with an extension (`allValues`, `fromString`), not the `typealias`.
2. **Drop `typealias` emission**: No `typealias X = String` at all; consumers refer to the enum directly.

### Systemic (unblocks 132 incomplete folders)

3. **Map interfaces to concrete structs**: For `InputLocation`, `ClassificationType`, etc., emit the concrete struct name (`inputlocation`, `classificationtype`) as the field type, not the protocol.
4. **Replace `Any` with a sendable container**: Use a generic `JSONValue` type (as the plan doc notes was done for `AccessGovernanceCP`).
5. **Suppress `description` for structs with a real `description` field**: Omit the `CustomStringConvertible` extension or use a different computed property name.
6. **Fix description interpolation**: Cast `Date?` to `String` or omit; cast collections to debug description.
7. **Map Go-only types**: `byte` → `UInt8`, provide `common`/`http` equivalents in `OCICommon`.
8. **Stop splitting enums into `*_enum.swift`**: Keep enums in their model files; update target excludes accordingly.

## What Cannot Be Inferred

- **Language**: Could be Java, Python, or a custom tool. The header comment says "Go to Swift conversion" and all sources are Go, so likely Go→Go→Swift (intermediate representation then Swift) or Go→Swift directly.
- **Exact AST mapping**: Without the generator source, I cannot verify whether it parses Go AST or does text-to-text regex.
- **Why 132 folders are incomplete**: Could be a whitelist/blacklist, incremental conversion, or prior tool version limits. The plan doc says "First compile all local service directories," implying many folders were intentionally excluded for now.
